## Totals

- MACs 81.9 M; estimated array cycles 348,032 (ideal 320,000, utilisation 92%) = 3.48 ms at 100 MHz (RTL measured 4.1 ms matmul-busy with ROM weights).
- Weight bytes streamed 1,250.0 KiB (static + runtime-packed K^T/V); activation DMA 873.0 KiB (~0.56 ms at 16 B/cycle).
- UB: peak 40.0 KiB with liveness-based reuse (live-set lower bound 40.0 KiB), vs 969.0 KiB without reuse; 98 UB buffers; DDR staging 993.0 KiB.
- Fusion: 73 matmul+requant(+act) ops; 280 IR ops -> 255. 2,336.0 KiB of int32 accumulators never leave ACC; a host-side requant would have cost 2,920.0 KiB of DMA.

Cycle model: MATMUL streams 1 row/cycle; weight tile load 16 cycles, hidden behind a previous MATMUL of >= 16 rows; 32-cycle drain at each SYNC on the matrix unit; ACTIVATE overlaps the array. DMA not included.

- Current: 31 TPU kernels separated by 31 host steps; 873.0 KiB of activation DMA (LN/softmax/GELU/residual inputs and outputs, K/V heads out for packing).
- Future: one program, no host steps, 9.0 KiB DMA (image in, features out). GELU moves into the fc1 ACTIVATE (fc1->fc2 in one kernel), the residual add into ACTIVATE.eltwise or the VPU, LN/softmax into the VPU, and K^T/V come straight from the UB. A single program only fits the 2048-entry instruction FIFO with the compact encoding (~763 instrs).
- P.V weights need no transpose: a V tile's weight word t is UB row (token 15-t) of V, so the UB->weight path only needs a reversed row order; K^T needs a 16x16 transpose (or a column-read mode).
